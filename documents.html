Accessible Documents

Create clear, structured documents that people can navigate, understand, and use with assistive technologies.

Module Overview

Instructional documents are often an essential part of a course. Making these documents accessible helps ensure that all learners can understand, navigate, and interact with the information they contain. Creating an accessible document means considering both what the document looks like and how it is structured behind the scenes.

In this module, you will learn how to create accessible Word and Google Docs documents, identify and fix common PDF accessibility issues, and format Excel and Google Sheets for accessibility. You will also learn how to use built-in accessibility checkers to identify and correct common issues.

The strategies in this module focus on creating clear document structure, using appropriate headings and lists, creating accessible links and tables, adding alternative text to images and charts, and ensuring that documents can be interpreted correctly by assistive technologies.

Learning Objectives

By the end of this module, you should be able to:

  • Create documents with a clear and logical heading structure.
  • Use built-in styles and formatting tools to communicate document structure.
  • Create accessible bulleted and numbered lists.
  • Create and structure data tables appropriately.
  • Write meaningful and descriptive link text.
  • Provide appropriate alternative text for meaningful images.
  • Identify when a complex image requires a long description.
  • Use readable fonts, appropriate formatting, and sufficient color contrast.
  • Avoid using color alone to communicate important information.
  • Use accessibility checking tools to identify potential barriers before sharing a document.

Why Create Accessible Documents?

Consider how students might interact with a document you provide.

Some students may:

  • Read it on a laptop or desktop computer.
  • View it on a phone or tablet.
    • Headings

    Headings do more than make sections of a document stand out visually. They provide structure and organization, helping readers understand how information is grouped and how different sections relate to one another.

    For sighted readers, a change in font size, bolding, or spacing may visually signal that a new section has begun. Assistive technology, however, relies on the document's underlying structure to identify headings. Simply making text larger or bold does not necessarily make it a heading.

    Using built-in heading styles in Microsoft Word or Google Docs creates that underlying structure. It allows screen reader users to identify and navigate between sections of a document and helps all readers scan content, locate information, and understand the organization of the material.

    Think of headings as the outline or roadmap of your document. If someone reviewed only the headings, they should be able to understand how the document is organized.

    Rather than formatting text to look like a heading, use the application's built-in heading styles to make it a heading.

    Use Built-In Heading Styles

    Headings help organize longer documents into sections and subsections.

    Instead of manually changing the font size, color, or weight to make text look like a heading, use the built-in heading styles available in Microsoft Word or Google Docs.

    For example:

    • Heading 1 — Course Accessibility Guidelines
    • Heading 2 — Documents
    • Heading 3 — Heading Structure
    • Heading 3 — Images

    Built-in headings provide an underlying structure that assistive technologies can recognize.

    A screen reader user may navigate from heading to heading rather than reading an entire document line by line. Headings can also make documents easier for everyone to scan and understand.

    Keep the Hierarchy Logical

    Think of headings as an outline.

    If Heading 2 introduces a section, Heading 3 can identify a subsection within it.

    Avoid choosing a heading simply because you prefer its visual appearance.

    The heading level should communicate where the section belongs within the hierarchy of the document.

    Microsoft Word Documents

    Use the built-in structural tools, not visual formatting alone

    • Use built-in Styles for headings and maintain a logical hierarchy.
    • Use Bullets and Numbering tools instead of manually typed symbols or numbers.
    • Use descriptive link text that communicates the destination or action.
    • Use paragraph formatting rather than the Enter key to create space between paragraphs.
    • Add meaningful alt text to informative images or mark decorative images appropriately.
    • Use simple tables for data and identify the appropriate header row.
    • Be sure all your text and images are enclosed in the text box.

    Note: Structure should be meaningful to assistive technology—not just visually apparent.

    Finish With Accessibility in Mind

    • Maintain sufficient color contrast and do not rely on color alone.
    • Avoid excessive ALL CAPS, italics, underlining, decorative fonts, and dense paragraphs.
    • Set the document language so assistive technology can pronounce content appropriately.
    • Use a meaningful document title and filename.
    • Run Word’s Accessibility Checker, review the findings, correct issues, and check again.

    Setting Up Microsoft Word (For Best Accessibility Results)

    Add metadata to your file by navigating to Info > Properties.

    Turn on all formatting marks (non-printing characters). This will enable you to see where you may have used paragraph returns to create space rather than using paragraph formatting. You must remove any of these instances before exporting to a PDF.

    Create Accessible Source Content

    • Use the Styles menu for headings and maintain a logical hierarchy.
    • Use built-in bulleted and numbered lists.
    • Write descriptive links that make sense when encountered independently.
    • Provide meaningful alt text for informative images.
    • Use tables for data, keep structures straightforward, and consider how cells will be navigated sequentially.
    • Maintain sufficient contrast, clear formatting, adequate spacing, and manageable paragraph lengths.

    Be Careful When Converting

    • An accessible Google Doc does not guarantee that every exported format will remain accessible.
    • Downloading or converting a Google Doc—especially to PDF—can change accessibility.
    • The new file should be checked separately after conversion.
    • Accessibility needs to be evaluated in the format you ultimately provide to students.

    PDFs

    Does Your Document Really Need to be a PDF?

    What Makes a PDF Accessible?

    • Accessible PDFs generally rely on tags that communicate structure and meaning to assistive technology.
    • Tags can identify headings, paragraphs, lists, tables, images, and links. Think of tags as the structural information behind the visual document.
    • Reading order must follow a logical sequence.
    • The PDF itself must be evaluated—not only the source document.

    “Save as PDF” Does Not Mean Accessible

    • Conversion can affect tags, reading order, headings, lists, tables, links, images, alt text, and document properties.
    • Always check the PDF after conversion.
    • If the PDF is what students receive, the PDF is what you need to evaluate.

    Accessible source ≠ automatically accessible PDF

    Scanned PDFs Need Special Attention

    • A scanned PDF may contain pictures of pages rather than machine-readable text.
    • If you cannot select or search the text, the PDF may be image-based.
    • After OCR, the file may still need tags, headings, reading order, alt text, table structure, language information, and other corrections.
    Which Format Should I Share: Word, Google Docs, or PDF?

    Choose the format that best supports how students need to access and use the information.

    Microsoft Word

    Good when students benefit from flexible, editable, structured source content.

    Google Docs

    Good for web-based access, collaboration, and maintaining accessible source content.

    PDF

    Useful when a fixed-format document is needed. For example, when signatures are needed. Note: these require separate accessibility verification.

    Do not convert to PDF automatically just because that is your usual workflow.

    Excel and Google Sheets

    Accessible Spreadsheets: Core Practices

    • Organize spreadsheet content with a clear and logical structure.
    • Use headers so rows and columns can be understood in context.
    • Add alternative text/long descriptions to meaningful images, charts, and graphics.
    • Do not rely on color alone to communicate information.
    • Use an accessibility checker when available, then review the spreadsheet manually.
    Color Contrast

    Color Contrast is a measure of the difference in perceived brightness between two colors. The brightness difference is expressed as a ratio ranging from 1.1 (white on white) to 21:1 (black on white).

    In WCAG 2.1 AA, the following three success criteria address contrast:

    1.4.3 Contrast (Minimum)

    The visual presentation of text and images of text has a contrast ratio of at least 4.5:1, except for the following:

    • Large Text (18 pt or larger): Large-scale text and images of large-scale text have a contrast ratio of at least 3:1.
    • Incidental: Text or images of text that are part of an inactive user interface component, that are pure decoration, that are not visible to anyone, or that are part of a picture that contains significant other visual content, have no contrast requirement.
    • Logotypes: Text that is part of a logo or brand name has no contrast requirement.

    Text color contrast ratio examples:

    • This may look like it passes color contrast but it's only a ratio of 3.97:1. It is hex value #007BFF.
    • This also fails. It has a ratio of 2.49:1, and a hex value #6FB46A.

    1.4.11 Non-Text Contrast

    The visual presentation of the following has a contrast ratio of at least 3:1 against adjacent color(s):

    User Interface Components

    Visual information required to identify user interface components and states, except for inactive components or where the appearance of the component is determined by the user agent and not modified by the author.

    For example: A group of white social media icons on a black background demonstrating that each icon has a unique user interface component.

    Note: If an element changes state, such as after user interaction, then that state must also meet 3:1 color contrast.

    Graphical Objects

    Parts of graphics required to understand the content, except when a particular presentation of graphics is essential to the information being conveyed.

    So, what do we do with logos that have text?

    Logos that contain text does not have a contrast requirement.

    Which other types of text don't have a contrast requirement?

    There are four types of "incidental text" defined by WCAG 2.1:

    1. Inactive: This refers to elements like those that are greyed out because they're inactive. These are visually identified by their lower contrast state.
    2. Pure decoration: This is decorative text that is not meant to be read. For example, an image that is blurred. It's not meant to be read.
    3. Not visible to anyone: Text that is meant to be hidden. There is no contrast requirement until is becomes visible.
    4. Part of a picture that contains significant other visual content: This refers to text in the picture that is not an important part of the image. This rule can be a difficult one. You will have to determine the context of the image and then make a decision on whether the text is important.

    Readable Text, Lists, and Links

    Use Readable Text and Formatting

    Accessibility also involves making the document comfortable to read.

    Choose clear, readable fonts and maintain sufficient font size.

    Avoid excessive use of:

    • ALL CAPS
    • Italics
    • Underlining
    • Decorative fonts
    • Dense blocks of text

    Use adequate spacing and break long sections into shorter paragraphs.

    Use Built-In Lists

    Lists are an effective way to organize related information, break up dense content, and make documents easier to scan. But just as text that looks like a heading is not necessarily a true heading, text that looks like a list may not actually contain list structure.

    When creating a list in Microsoft Word or Google Docs, always use the application's built-in bulleted or numbered list tools rather than manually typing bullets, dashes, asterisks, or numbers.

    Built-in list formatting provides underlying structure that assistive technology can recognize. A screen reader can communicate that the user has entered a list, how many items the list contains, and where individual list items begin and end. This gives the reader important context about how the information is organized.

    Don't Use Lists Just for Appearance. Lists should communicate a meaningful relationship among items. Avoid using bullets simply to indent text or create a particular visual layout.

    Create Meaningful, Descriptive Links

    Links are an important part of how we navigate digital documents. They connect students to readings, assignments, websites, videos, course resources, and other information. The words you choose for a hyperlink—known as link text—should clearly communicate where the link leads or what will happen when the student selects it.

    A descriptive link should make sense on its own, without requiring the reader to interpret the surrounding sentence.

    For example:

    To review the assignment requirements, click here.

    The words click here provide no information about the destination. A more accessible approach incorporates the destination into the link itself:

    Review the Final Project Assignment Requirements.

    This is especially important for people who use screen readers. Rather than reading an entire document from beginning to end, a screen-reader user may navigate directly from one link to another or generate a list of the links contained in a document. When links are presented outside their surrounding context, a list such as click here, read more, learn more, and more information provides very little useful information.

    Compare that experience with encountering links named:

    • Download the Course Syllabus (Word)
    • Review the Final Project Instructions
    • Visit the TLC Digital Accessibility Resources
    • Register for the Accessibility Workshop

    The purpose of each link is immediately apparent. Descriptive link text benefits other readers as well because it makes a document easier to scan and helps students locate resources quickly.

    Write the Destination, Not the Direction

    One useful way to think about link text is to focus on the destination or action rather than instructions for operating the link.

    Instead of writing: "Click here to download the syllabus", write: "Download the Course Syllabus".

    Instead of: "For more information about the assignment, read more", write: "Review the Research Assignment Guidelines".

    Words such as click here also assume that the user is interacting with the document using a mouse. A student might instead activate a link with a keyboard, touchscreen, voice command, or assistive technology. Describing the destination avoids making assumptions about how someone interacts with the document.

    Avoid Using the URL as the Link Text

    Long web addresses can also create accessibility and readability problems when they are placed directly into the body of a document.

    Instead of displaying a long web address, use meaningful text such as: "Review the Accessible Documents Guide".

    There are situations in which displaying the full URL may be appropriate—for example, when a document will be printed and readers will need the web address. For primarily digital documents, however, descriptive link text is usually the better choice.

    Avoid Repeating Generic Link Names

    Link text should also help distinguish one destination from another.

    Imagine a document containing several resources labeled: "Learn More". Even though each link may lead somewhere different, the link text does not communicate those differences.

    Instead, identify each resource. For example: "Learn More About Alternative Text" or "Learn More About Color Contrast". This gives each link a meaningful identity and makes navigation more efficient.

    Include Useful Information in the Link Text

    When appropriate, tell students what they are opening or downloading.

    For example: "Download the Accessible Documents Checklist (PDF)" or "Download the Assignment Template (Word)".

    Including the file type can help students know what to expect before opening or downloading the resource.

    The same principle applies when the link performs an action. Link text such as "Register for the Workshop, Email the Course Instructor, or Download the Syllabus" communicates both the purpose and expected result.

    Keep Link Text Concise

    Descriptive does not mean excessively long. The goal is to provide enough information to understand the purpose of the link without turning an entire paragraph into a hyperlink.

    For example: "Review the Week 3 Assignment Instructions" is more useful than linking a full sentence such as: "Click here if you would like to review all of the instructions and requirements for the assignment that is due during Week 3".

    Aim for link text that is specific, concise, and meaningful when read independently.

    Tables

    Tables should be used to organize data, not to control the visual layout of a document.

    One of the most important steps in creating an accessible table is identifying the appropriate header row, and when applicable, header column. Headers tell the reader what the data represents.

    Note: There is no way to create an accessible table in Google Docs because the user is unable to tag row and column headers.

    In Microsoft Word, create a table by using Insert > Table. Be sure to check the box to identify the first row as the header row.

    Be sure to write a meaningful title to introduce the table.

    If your table continues across multiple tables, configure the header row to repeat at the top of each page.

    Items to avoid when creating a table

    • Merged cells
    • Split cells
    • Multiple levels of column headings
    • Blank rows or columns used for spacing
    • Nested tables
    • Irregular arrangement of cells
    • Blank cells (instead use a term such as "No data")
    • Using color alone to convey meaning

    If your table is complicated, ask yourself whether it can be divided into two or more tables.

    Test that you can navigate your table by using your keyboard to tab to each cell. The order should be from top left to bottom right.

Key Takeaways

Remember these key principles when creating instructional documents:

  • Use structure, not appearance, to communicate organization.
  • Use built-in heading styles and list tools.
  • Use descriptive link text.
  • Create tables using appropriate table features and header rows.
  • Avoid nested tables and merged cells.
  • Add alternative text to meaningful images, charts, and graphics.
  • Provide long descriptions for complex data visualizations when needed.
  • Do not rely on color alone to communicate information.
  • Use clear, readable text and sufficient color contrast.
  • If you want to use a PDF, make sure it's the format that is appropriate.
  • Check PDFs for tags, reading order, titles, alternative text, and table structure.
  • Give spreadsheets a clear and logical structure.
  • Use accessibility checkers to identify and correct issues in the final format that students will receive.
  • Always review the document manually in addition to using an accessibility checker. There are items that automation can't check or will check but get it wrong!
