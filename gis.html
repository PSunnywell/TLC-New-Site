Accessible GIS and Spatial Data

Create accessible maps, geospatial visualizations, and data dashboards that communicate meaningful spatial information.

Module Overview

Geographic information systems (GIS) use maps, layers, symbols, geographic coordinates, and interactive controls to communicate spatial relationships. Students may need to interpret locations, compare regions, investigate patterns, and analyze geographic data. An accessible learning experience should not require vision, color discrimination, or mouse-only interaction to understand the essential information.

This module adapts the accessibility practices in UCLA Teaching and Learning Center’s Creating Accessible Tableau Dashboards checklist to GIS and geospatial instruction. Tableau-specific steps are labeled as such; the source PDF does not provide software-specific instructions for ArcGIS, QGIS, or other GIS applications.

Learning Objectives

  • Identify keyboard and screen-reader barriers in maps and dashboards.
  • Provide structured data and meaningful descriptions of geographic patterns and spatial relationships.
  • Use accessible map labels, legends, symbols, and color contrast.
  • Test focus order, zoom, responsive layouts, and interactive controls.
  • Design alternatives to hover-only features, dense visualizations, and inaccessible map interactions.
  • Evaluate the published map and data using manual accessibility checks.

How to Make GIS and Spatial Visualizations More Accessible

Keyboard Access and Supplemental Data

Checklist reference: 2.1.1 Keyboard; 1.3.1 Info and Relationships

  • Test whether students can reach and operate map controls, filters, layers, and data marks using only a keyboard.
  • The Tableau checklist recommends providing a properly structured supplemental data table when marks cannot be navigated reliably. Include clear column headers, a caption, and a link or accessible view alongside the visualization.
  • In Tableau, test the View Data option and its keyboard access; do not assume the same shortcut or functionality applies to other GIS products.
Avoid Hover-Only Interactions and Keyboard Traps

Checklist reference: 2.1.1 Keyboard; 2.1.2 No Keyboard Trap

  • Do not make important information available only by hovering over map features or chart marks. Provide keyboard-operable alternatives.
  • Test embedded maps and dashboards to ensure users can move focus into and out of them. An iframe may require focus-management work by the developer.
  • Ensure interactive map controls have accessible names and visible focus.
Logical Focus Order and Screen-Reader Testing

Checklist reference: 2.4.3 Focus Order; 1.1.1 Non-Text Content

  • Check that the first Tab reaches the first expected interactive element and subsequent Tab presses follow a logical sequence.
  • The source checklist identifies Tableau Dashboard > Tab Order as a place to configure order. Other GIS products have different controls.
  • Test the final published visualization with NVDA on Windows or VoiceOver on macOS; verify whether map data and controls can actually be understood.
Color Contrast and Non-Color Cues

Checklist reference: 1.4.3 Contrast; 1.4.11 Non-Text Contrast; 1.4.1 Use of Color

  • Aim for at least 4.5:1 contrast for normal text and 3:1 for necessary graphical objects and controls, as described in the source checklist.
  • Do not encode spatial categories, risk levels, or trends with color alone. Pair color with patterns, symbols, line styles, or explicit labels.
  • Check choropleth legends and map symbols in grayscale and under color-vision simulations. Shading used to distinguish rows or regions must remain legible.
Descriptive Map Titles, Labels, and Long Descriptions

Checklist reference: 2.4.6 Headings and Labels; 1.3.1 Info and Relationships; 1.1.1 Non-Text Content

  • Give each map or dashboard a descriptive title. Label axes and quantitative units when charts are present.
  • Place labels near geographic features or data marks where practical; use callouts if labels will not fit. Do not rely on an unexplained color legend alone.
  • Provide a long description explaining the map purpose, spatial patterns, major comparisons, relevant locations, and key conclusions.
Responsive Layout, Typography, and Spacing

Checklist reference: 1.4.4 Resize Text; 1.4.12 Text Spacing; source best practices

  • At 200% browser zoom, check for clipped text, overlapping labels, missing controls, and content disappearing from view. Also test narrower viewport widths.
  • The source recommends readable sans-serif text, at least 12 pt (16 px), mixed-case labels, and adequate padding and white space.
  • For Tableau labels, check that Allow labels to overlap other marks is off; use leader lines where appropriate.
Targets, Animation, and Dense Data Marks

Checklist reference: 2.5.8 Target Size; 2.2.2 Pause, Stop, Hide; source best practices

  • Ensure clickable features and controls have sufficient target size and spacing; the source references 24-pixel targets.
  • Allow users to disable or pause animations. Ensure changing information is available in text and announced appropriately when necessary.
  • The Tableau checklist warns that views with over 1,000 marks may be rendered as static images. Reduce or aggregate marks and offer the underlying data instead of assuming every dense visualization is accessible.
Accessible Data Downloads and Map Alternatives

Checklist reference: 1.1.1 Non-Text Content; 1.3.1 Info and Relationships

  • Provide a structured data table and downloadable underlying data (for example CSV or Excel) when suitable.
  • For GIS-specific maps, identify coordinate systems, locations, geographic units, and relationships in accompanying text or structured data. This is an application of the checklist principles, not a GIS-specific instruction from the PDF.
  • A data download alone does not communicate every spatial relationship: pair it with a meaningful written summary of geographic patterns.
Dashboard Organization and Captions

Checklist reference: Source best practices

  • Limit dashboard complexity. The source recommends about three to four worksheets in a Tableau dashboard.
  • Provide a plain-language summary of trends and insights; the checklist notes Tableau Worksheet > Show Caption.
  • Use descriptive links rather than displaying bare URLs; include an accessibility contact method for issues with the published visualization.
Test and Publish the Final Experience

Checklist reference: Combined source checklist practices

  • Test the exact published map or dashboard with keyboard-only navigation, screen readers, browser zoom, grayscale, and narrow screens.
  • Check interactive features, filtering, focus, text labels, and access to equivalent data—not merely whether the page passes an automated checker.
  • When software cannot provide equivalent access to a task, supply an alternative that meets the same instructional objective.

Key Takeaways

  • Maps and dashboards need keyboard-operable controls and logical focus order.
  • Provide accessible underlying data and meaningful descriptions of geographic relationships and patterns.
  • Do not rely on color, hover, or graphical marks as the only way to obtain information.
  • Use descriptive labels, adequate contrast, readable text, and responsive layouts.
  • Test the final published visualization manually with assistive technologies.
  • Tableau-specific menu paths and rendering limitations in the source should not be assumed to apply to other GIS software.
